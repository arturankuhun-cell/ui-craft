ui-craft — воркфлоу для агентов, которые пишут UI: от чтения существующих токенов до проверки результата. Пять фаз (read the room → direction → architecture → build → verify → critique), справочники по типографике, цвету, раскладке, motion, a11y и React-перфомансу, плюс три скрипта без зависимостей. MIT.

Скилл для ИИ-агентов, которые пишут интерфейсы. Не «сделай красиво», а конкретный воркфлоу с проверяемым результатом: прочитать кодовую базу → принять решение → спроектировать → собрать в правильном порядке → проверить скриптами и глазами → убрать лишнее.

Интерфейсный код ломается в двух направлениях, и оба дорогие.

Вниз — сломанные раскладки, недоступные контролы, провалы контраста, layout shift, ре-рендеры на каждый введённый символ.

Вбок — всё технически корректно и мгновенно забываемо: фиолетовый градиент на скруглённой карточке с тенью под ней.

Большинство советов давит в одну сторону. Дизайн-скиллы требуют быть непохожими и не дают способа проверить результат. Гайды по производительности предлагают спиннер и называют это вкусом. Этот скилл построен вокруг мысли, что дизайны сходятся потому, что их никто не проверяет. Каждое правило здесь имеет соответствующую проверку.

Что внутри
Воркфлоу из шести фаз. Порядок важен меньше, чем сам факт: верификация обязательна и не пропускается.

0  Read the room      существующие токены, паттерны, стек — до написания разметки
1  Direction          решение, сформулированное одним коротким планом
2  Architecture       компоненты, владение состоянием, поток данных
3  Build              токены → семантика → стили → motion
4  Verify             запустить, посмотреть, измерить, починить
5  Critique           убрать одну вещь, записать что пробовал
Read the room требует ответить из кода, а не из памяти: какая система стилизации, где живут токены, на что похож соседний компонент, как грузятся шрифты, какая плотность у существующих экранов. Tailwind v3 config и v4 @theme несовместимы; писать #3b82f6 там, где есть --color-primary — самая частая причина разложения кодовой базы.

Direction — четыре решения со значениями, а не мудборд: предмет (что это, для кого, одна задача экрана), токены (4–6 именованных цветов с hex, гарнитуры с ролями, шаг отступов, шаг motion), композиция (ASCII-wireframe, куда идёт глаз первым), ставка (одна идея, делающая интерфейс не-шаблонным). Правило: смелость тратится один раз. Запоминающийся герой и дисциплина везде читаются как уверенность; та же энергия везде — как незаконченный мудборд. Если в плане нет ни одного hex и ни одного числа, это ещё не решение.

Architecture — границы компонентов до того, как файлы выросли. Делить, когда компонент владеет своим состоянием, под-часть переиспользуется, функция перевалила за ~80 строк смешанных забот, одна строка className повторяется в трёх файлах. Не делить, когда части не описать и не протестировать отдельно, понадобятся пропсы на каждую визуальную вариацию, или кусок — это 10 строк разметки. Card с пропом variant бьёт три почти одинаковые карточки. Самая частая архитектурная ошибка — класть derived-значения в стор: это бесплатно даёт sync-баги, устаревшие значения и двойные рендеры. Что можно посчитать во время рендера, не хранить.

Build идёт в фиксированном порядке, потому что motion поверх нестабильной раскладки — это анимация неправильной вещи.

Семантика до стилизации. <button type="button"> вместо <div onClick>, <a href> вместо <span onClick>, <button aria-pressed> для тумблера, <select> или radio в <fieldset> вместо кастомного дропдауна, <button aria-expanded aria-controls> для раскрытия, <table> с <th scope> вместо div-грида с прикрученными ARIA-ролями, <label for> вместо placeholder. placeholder — не лейбл: он исчезает ровно тогда, когда нужен. Это слой, который дорого переделывать: div с onClick не станет доступным без переписывания.
CSS-архитектура. Почти все «стили сломались» — это несчастные случаи специфичности: два класса на одном элементе, один написан позже, оба молча дерутся. Один класс на элемент; !important никогда (это признание слишком жадного селектора — почини селектор); descendant-селекторы привязывают к структуре (.card > .card-header > h3 ломается, как только заголовок обернут в div, поэтому .card__title — класс говорит, что это, а не где живёт); скоупинг по data-атрибуту или классу-обёртке, не по id страницы; @layer reset, tokens, base, layout, components, utilities, overrides — overrides последним, чтобы они были намеренными, а не симптомом. Container queries побеждают viewport-медиазапросы для компонентов: карточке в сайдбаре 300px и той же карточке во всю ширину нужны разные раскладки, и ширина вьюпорта не может их различить. Это разница между библиотекой компонентов и стопкой стилей страниц.
Типографика. Тело не меньше 16px (ниже iOS зумит на фокусе), мера 60–75ch с жёстким потолком ~80ch, line-height 1.5 для sans и 1.6 для serif (серифу нужен воздух из-за контраста штрихов), заголовки 1.1–1.25, трекинг дисплейного −0.02…−0.045em при нулевом трекинге в тексте и +0.06em у лейблов, масштаб 1.2–1.25, одна гарнитура или две явно разные. Оптическое выравнивание бьёт математическое: круг должен висеть чуть ниже квадрата, чтобы казаться ровным, левый край заголовка на H утоплен внутрь бокса. Когда что-то выглядит криво при верной математике — оно и есть.
Цвет. Цвет несёт смысл раньше декорации. Семь ролей с явным описанием работы и провала: фон, поверхность, основной текст, вторичный текст (самое частое нарушение WCAG в «дизайнерских» интерфейсах), граница, акцент (одна вещь на экран), семантика (кодирование только оттенком лишает смысла пользователей с дальтонизмом). Контрастные пороги AA/AAA — не переговорное: 4.5:1 для текста тела, 3:1 для крупного, 3:1 для границ, иконок, фокус-колец и марок графиков. Тёмная тема — не инверсия. Инвертировать светлоту, и каждое насыщенное цвет завибрирует напротив дополняющего — тот самый glow, который делает дешёвые интерфейсы дешёвыми. Держим hue, сдвигаем lightness, снижаем chroma на больших поверхностях; текст не чисто белый (#e6edf3 на #0d1117 читается чище #ffffff на #000000). Тёмную палитру выводим из брендового hue, а не подбираем заново. Elevation в тёмной теме идёт от светлоты, а не от тени: тени на тёмном фоне почти не видны.
Раскладка и плотность. Пять тиров отступов от micro (2–6px) до macro (64–96px+). Плотность — решение, а не случайность: торговый терминал и маркетинговый сайт используют одни токены и выбирают разные тиры. Правила, выживающие при реальном контенте: проектировать от худшего случая (40-символьная немецкая строка, 12-значное число, пустой список, 500 элементов); min-width: 0 на flex-детях без чего длинное слово отказывается сжиматься и взрывает раскладку; ломать на естественных швах контента, а не на ширинах устройств; тестировать на 320px; фиксированная высота на элементе с текстом — баг, ждущий чужой строки.
Motion. Движение объясняет изменение состояния; если не объясняет — это шум. Таблица длительностей и кривых:80–120ms на нажатие, 120–200ms на hover/focus, 150–250ms на появление мелкого элемента, 250–400ms на панель и модалку, 300–500ms на смену страницы, 1200–1600ms на скелетон. Анимировать transform и opacity — единственные свойства, которые композитор обрабатывает без layout и paint; width, height, top, left форсируют layout каждый кадр. Вход и выход симметричны, иначе элемент выглядит глюком. Одна оркестрованная анимация лучше stagger на всём: fade-and-slide-up на каждой секции — подпись сгенерированной страницы. prefers-reduced-motion соблюдается не как чекбокс, а как причина вообще сомневаться в крупном параллаксе и автоплее.
Текст, который продакшнится. Копирайт интерфейса — дизайн-контент, пишется во время сборки. Именовать тем, что пользователь понимает («Notifications», не «webhook config»). Кнопка говорит, что произойдёт («Save changes», не «Submit»; если кнопка «Publish», то тост «Published»). Ошибка объясняет и чинит: не «Invalid input», а «Enter a date after today» — без извинений, обвинений и стектрейса. Пустое состояние — приглашение. Одна идея на элемент: у элемента с двумя задачами два дизайна дерутся.
Verify — фаза, ради которой скилл существует. Пять проверок, первые две занимают секунды и ловят большинство проблем.

Статический аудит — ловит то, чего не видно на скриншоте: хардкод цветов, magic numbers, отсутствующие focus-состояния, a11y-запахи, опасности специфичности.
Контраст — каждая пара токенов, обе темы.
Визуально — скриншот стоит тысячи токенов спекуляций. Смотрим и проверяем конкретно: порядок чтения тот ли, что задумано; ничего не обрезано, не перекрывается, не сидит под неудобным углом; акцент использован один раз; пустота читается как намеренность, а не как дыра; держит ли мобильная ширина.
Клавиатура — весь флоу табом: каждый интерактивный элемент достижим, кольцо фокуса видно на каждом, модалки ловят фокус и закрываются по Escape, нет невидимых клик-таргетов, логичный порядок совпадает с визуальным. И пользоваться: Space переключает, Enter отправляет, стрелки двигают внутри группы.
Производительность — диагностика по симптому: джиттер на скролле → анимируется layout/paint вместо transform; лаг ввода → ре-рендер всего дерева на нажатие, состояние выше инпута; список тормозит → все строки в DOM, виртуализировать после ~200; hydration warning → Date.now()/Math.random() в рендере; FOUC → шрифты блокируют, нужен font-display: swap и preload; layout shift → у изображений нет размеров.
Critique применяет правило Шанель перед сдачей: убери одно украшение. То, что добавил последним и что тебе нравилось больше всего, обычно и надо резать. В конце сводки пишутся две строки — Tried: и Remove next time:. Именно эта заметка останавливает каждый проект от схождения в один и тот же вид.

Скрипты
Три CLI-утилиты без зависимостей, чистый Node.

node scripts/audit-ui.mjs src/                        # статический аудит
node scripts/audit-ui.mjs src/ --json                 # машинный вывод
node scripts/audit-ui.mjs src/ --strict               # warnings становятся errors

node scripts/contrast.mjs "#1e293b" "#ffffff"         # произвольная пара
node scripts/contrast.mjs "#1f2328" "#ffffff" --large --aaa
node scripts/contrast.mjs --from src/styles/tokens.css   # все пары токенов

node scripts/shot.mjs http://localhost:5173 --out .ui-qa
node scripts/shot.mjs http://localhost:5173 --path /settings --viewports mobile,desktop
node scripts/shot.mjs http://localhost:5173 --full
audit-ui.mjs сканирует .tsx .jsx .ts .js .css .scss .html .vue .svelte и возвращает ненулевой exit code при error-находках.

contrast.mjs реализует WCAG 2.x с sRGB-порогом 0.04045, а не значением 0.03928 из WCAG 1.x, которое до сих пор гуляет по скопированным сниппетам. Возвращает ненулевой exit code, если какая-либо пара не проходит.

shot.mjs идёт по стратегии в порядке приоритета: Playwright, если резолвится из проекта; browser-use, если CLI есть в PATH (npm install не нужен); иначе печатает готовую инструкцию. Всегда выходит с 0, кроме --strict — отсутствие инструмента для скриншота не является провалом аудируемого кода.
